이미지 전처리와 학습

캐릭터별 50~150장을 모으고 의상이 일관된 이미지를 선별했습니다. SAM3로 배경을 제거해 캐릭터 특징에 집중하도록 했습니다.

자동 태깅 후 이미지를 한 장씩 검수했습니다. 배경 태그를 지우고 캐릭터를 부르는 트리거 워드를 넣었습니다.

태깅에는 SmilingWolf/wd-convnext-tagger-v3, 학습에는 kohya_ss, 생성에는 ComfyUI를 사용했습니다. 결과는 외형·의상·포즈를 눈으로 비교했으며 정량 유사도 평가는 아닙니다.

이미지와 한국어 지시를 영상 프롬프트로

이미지를 읽는 모델에 한국어 연출 지시를 함께 넣고, MiniMax H3용 영어 프롬프트를 작성하도록 구성했습니다.

변환할 때 지키도록 한 규칙

  • 이미지에서 유지할 외형과 요청에 따라 바꿀 장면을 구분합니다.
  • 동작 순서·카메라·소리 지시를 보존하고, 요청하지 않은 이야기를 덧붙이지 않습니다.
  • 입력이 빠지거나 조건이 충돌하면 오류를 반환하도록 지시합니다.
모델과 연결 방식

Qwen3.8-27B 기반 파생 GGUF 모델을 IQ4_XS 양자화로 로컬 실행합니다. 한국어 해석과 응답성을 직접 확인해 선택했고 Ollama를 통해 ComfyUI에 연결했습니다.

두 클립의 프롬프트를 먼저 작성한 뒤 VLM을 해제해 GPU 메모리 경쟁을 줄이도록 구성했습니다. 다음 영상 생성에는 이전 클립의 마지막 프레임을 전달합니다.

출력 형식

대상 정의 → 요약 → 유지·변경할 특징 → 장면 연출 → 환경음 → 배경음악, 여섯 부분으로 작성합니다. 단일 클립 지시는 4~15초 범위로 구성했습니다.

시스템 프롬프트의 설계 규칙이며 모델이 항상 준수한다는 뜻은 아닙니다. 모델 성능 비교나 제작 시간 단축률은 측정하지 않았습니다.

LoRA 관리와 프롬프트 준비

Sync는 선택한 LoRA를 ComfyUI 폴더로 복사합니다. Analyze는 캡션에서 자주 나오는 특징을 모아 프롬프트로 준비합니다.

Python과 JavaScript로 검색·미리보기·설치 상태 확인·클립보드 복사를 연결했습니다.

구현과 한계

캡션 분석은 태그 빈도와 키워드 규칙 기반입니다. 원본은 이동하거나 삭제하지 않고 복사하며, 같은 이름의 파일 크기가 다르면 기본적으로 덮어쓰지 않습니다.

같은 크기의 파일을 건너뛰는 처리는 파일 내용의 해시 검증이 아닙니다. 캡션 분석과 LoRA 정보 출력은 커스텀 노드에서도 사용할 수 있습니다.
